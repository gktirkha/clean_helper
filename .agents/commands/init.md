# Command: init

**Entry point:** `lib/src/commands/init.dart` → `runInit({withNetwork, withDi, withTools})` (async)
**Runner:** `InitCommand` — `clean-helper init`

## Usage

```bash
clean-helper init [--network|-n] [--di|-d] [--tools|-t]
```

Run once, in a project fresh from `flutter create`.

## Sequence

`ensurePubspec()` runs first. `resolveUtilsPackage()`, `resolveLocalizationPackage()` and `resolveRouterPackage()` then give each package's name, import and `create` flag (defaults: `<app>_utils`, `<app>_localization`, `clean_router`, all created), and `resolveSlangSettings()` the slang settings. The rest is in `overview.md` → "`init` sequence". In brief:

1. `fvmUse()`, `generateAnalysisOptions()`, `runFlutterPubGet()`
2. `createDirectories()`, `generateFlutterGenFiles()`
3. The packages with `create: true`: `generateCleanRouterPackage()`, `generateLocalizationPackage()`, `generateUtilsPackage()`, then `addPackagesWorkspace()` for those created — no `workspace:` key if none are
4. The app: `generateCoreFiles()`, `createFeatureStructure()` for `home` (with `withDi`)
5. `installDependencies()`, `updateGitignore()`, `addVscodeConfig()`, `addFlutterAssetsToPubSpec()`
6. `addNetworkModule(runBuildRunnerAfter: false)` with `--network`; `generateToolsFiles()` with `--tools` comes after it
7. `runSlang()` in the localization package if created; `runBuildRunner()` in the utils package (if created) and the network package (with `--network`); then `runBuildRunner()` in the app and `runDartFormat()`
8. `sortPubspecDeps()` for the app and the created utils / localization pubspecs; `writeToolVersion()`

The package generators call `scaffoldPackage()` — `flutter create --template package`, delete the scaffold files (README, CHANGELOG, LICENSE, `.metadata`, `test/`, and `lib/<name>.dart` when the configured barrel is elsewhere), write an `analysis_options.yaml` that only includes the app's (or, with `use_root_analysis`, the root's) — and then:

- patch the pubspec tail (`resolution: workspace`, dependencies) via `patchPackagePubspec()`;
- write their sources with `overwriteFile`.

## What it generates

See `architecture.md` for the full tree. Key points:

- The utils package holds `Failure`, `UseCaseBase`, the Retrofit call adapter, `AppLogger`, `safeExecute`, `safeExecuteTask` and the rest, plus an injectable micro-package registering `BlocObserver`. Since 1.4.4 it no longer contains `RetrofitCallAdapter` / `RetrofitLogger`, and doesn't depend on `dio` or `retrofit`.
- `UseCaseBase` is in the utils package (`lib/src/use_case_base.dart`, exported from the barrel) since 1.7.0; `UseCaseBase.call` returns `FutureOr<TaskEither<Failure, ReturnType>>`. Earlier versions generated it in the app at `lib/core/domain/use_cases/use_case_base.dart`.
- The home feature is generated by `createFeatureStructure`, like `add-feature`, plus empty `data/` and `domain/` folders from `createDirectories()`.

## Dependencies

- **App runtime:** `flutter_bloc`, `go_router`, `get_it`, `injectable`, `freezed_annotation`, `fpdart`, `package_info_plus`, `flutter_svg`, `json_annotation`, `logger`, `flutter_localizations` (SDK)
- **App dev:** `build_runner`, `injectable_generator`, `freezed`, `flutter_gen_runner`, `json_serializable`
- **App workspace packages:** `clean_router`, `<app>_localization`, `<app>_utils` — added with `flutter pub add` and no `--path` (since 1.7.0); pub resolves them from the workspace
- **Utils package:** `flutter_bloc`, `fpdart`, `get_it`, `injectable`, `logger`, `<app>_localization`; dev `build_runner`, `injectable_generator`
- **Localization package:** `slang`, `slang_flutter`

## Notes

- `init` reads `clean-helper.packages.{utils,localization,router}`: names, barrel imports (the barrel is written at the import's path), `create`, `utils.module_name` (the `@module` class), `utils.call_adapter_name` (via `add-network-module`) and the slang keys under `localization`, which become `slang.yaml` and set the generated file and `translate_var` used by the barrel, `String.tr` and `safeCast`.
- Workspace packages are always added with `flutter pub add <name>` (no `--path`), created or not.
- The home feature's generators take `packageName` but otherwise match `add-feature`.
