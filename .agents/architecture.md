# Architecture of Generated Projects

What the templates produce. Keep this in sync when a template changes shape.

The app's `pubspec.yaml` lists all three packages under `workspace:` and as path dependencies. Each package pubspec has `resolution: workspace`.

## Workspace packages

### `clean_router`

- `CleanRouterBase`, the interface for feature routers: `routes`, `refreshStreams`, `redirect(context, state)`, and `priority` (lower wins).
- `CleanRouterRefresh`, a `ChangeNotifier` merging every router's `refreshStreams`, used as go_router's `refreshListenable`.

### `<app>_localization`

- `slang.yaml`, with output in `lib/src/generated`
- `assets/locales/en.locale.json`
- the `String.tr` extension

Slang runs inside this package.

### `<app>_utils`

```
lib/<app>_utils.dart                 barrel
lib/src/
├── app_logger.dart                  AppLogger (static)
├── bloc_observer.dart               AppBlocObserver
├── debouncer.dart
├── error_entity.dart
├── failure.dart                     Failure({message}); Failure.leftFromError(e)
├── type_definitions.dart            JsonDecodeFactory<T>
├── di/<app>_utils_module.dart       @module — registers BlocObserver
├── di/di_initializer.dart           @InjectableInit.microPackage → <App>UtilsPackageModule
└── functions/
    ├── get_current_function_name.dart
    ├── list_to_model_list.dart
    ├── safe_cast.dart               safeCast → Either<Failure, T>
    ├── safe_execute.dart            safeExecute(FutureOr<T>) → FutureOr<Either<Failure, T>> (eager)

```
lib/features/<f>/
├── di/<f>_module.dart                       add-feature --di
├── presentation/
│   ├── bloc/<f>/<f>_bloc.dart               @injectable; _event / _state are `part of`, @freezed
│   ├── page_providers/<f>_page_provider.dart   BlocProvider(create: diContainer) + navigation from DI

│   ├── <f>_routes.dart                      sealed class <F>Routes { static const <camel> = '/<kebab>'; }
│   ├── <f>_navigation.dart                  abstract class <F>Navigation { goTo<F>(context) }
│   └── <f>_router.dart                      @lazySingleton, implements CleanRouterBase
├── domain/                                  add-repo / add-entity
│   ├── entities/<r>_entity.dart
│   ├── repositories/<r>_repository.dart

    ├── constants/<f>_api_paths.dart         REST

## DI (get_it + injectable)

| Where | Annotation |
|---|---|
| Feature bloc | `@injectable` — a factory, because `BlocProvider` closes the bloc on dispose and a singleton would come back closed |
| Feature router, navigation impl | `@lazySingleton` / `@LazySingleton(as: …)` |
| Repository impl | `@Singleton(as: <R>Repository)` |
| REST datasource | `@Injectable(as: <R>DataSourceBase)` with a `@factoryMethod` factory |
| `NetworkModule`, `CoreModule`, `AppModule`, utils module | `@module` |

`ParseErrorLogger` is registered once, as `RetrofitLogger`, by `NetworkModule` (`@LazySingleton(as: ParseErrorLogger)`). Two older layouts differ:

- Projects initialised before 1.4.1 register it in the utils module instead. `add-network-module` detects this and skips its own registration, because GetIt throws on duplicates.
- When `packages.network` is configured, the tool can't see whether the external package registers one, so the REST datasource marks `errorLogger` `@ignoreParam`. injectable_generator otherwise emits `gh<ParseErrorLogger>()`, which throws if nothing is registered.

## Result type — fpdart `TaskEither`

With `result_type: task_either`, the default:

```
RetrofitCallAdapter<T> extends CallAdapter<Future<T>, TaskEither<Failure, T>>
  adapt(call) => safeExecuteTask(call)                  lazy: nothing runs until .run()
<R>DataSourceBase / Rest<R>DataSource   → TaskEither<Failure, <R>ResponseModel>
<R>Repository / <R>RepositoryImpl       → TaskEither<Failure, <R>Entity>   (impl not async; TaskEither is covariant)
Get/Post<R>UseCase                      → TaskEither<Failure, <R>Entity>
UseCaseBase.call                        → FutureOr<TaskEither<Failure, ReturnType>>
```

Callers run `await useCase(params).run()`. With `result_type: future_either`, `add-repo` generates the pre-1.4.2 shape instead: `Future<Either<…>>` with `async` repository methods, and `FutureOr<Either<…>>` in use cases.

retrofit_generator still emits `_setStreamType<Either<Failure, T>>` in `.g.dart` files. This is harmless.

## Network

| Piece | Location | Notes |
|---|---|---|
| `ApiPaths.baseUrl` | `core/network/constants/api_paths.dart` | |
| `NetworkModule` | `core/network/di/network_module.dart` | `BaseOptions` (User-Agent from `PackageInfo`), `ChuckerDioInterceptor`, `PrettyDioLogger`, `Dio` with the error, Chucker and logger interceptors, and the `RetrofitLogger` registration. `add-auth-interceptor` adds `AuthInterceptor` and a `@Named(DIKeys.noAuthDio)` Dio |
| `ErrorInterceptor` | `core/network/interceptors/` | `{"errors": [...]}` → `ErrorModel` |
| `RetrofitCallAdapter`, `RetrofitLogger` | `core/network/utils/` | Import the utils package. Projects before 1.4.4 have them in `packages/<app>_utils/lib/src/network/` |
| `<F>ApiPaths` | `features/<f>/data/constants/` | `static const <camelRepo> = '/api/<kebab-feature>/'` |

The REST datasource imports the call adapter from, in order: `retrofit_call_adapter.import`, then `packages.network.import`, then `../../../../core/network/utils/retrofit_call_adapter.dart` if it exists. If none of these applies, it relies on the utils import.

## Other generated pieces

- **Serialization:** models are `@freezed sealed class … implements <Entity>` with `fromJson`. Request models are `@JsonSerializable`.
- **Localization:** slang; `LocaleSettings.useDeviceLocale()` in bootstrap, `TranslationProvider` in `MainApp`.
- **Assets:** flutter_gen via `build.yaml`, output in `lib/generated/flutter_gen/`, colors from `assets/colors/colors.xml`.
- **Lints:** `analysis_options.yaml` is written by `init` for the app and each package.
