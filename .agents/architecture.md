# Architecture of Generated Projects

What the templates produce. Keep this in sync when a template changes shape.

---

## Layout after `init`

```
<app>/
├── lib/
│   ├── main.dart                      calls bootstrap()
│   ├── app/
│   │   ├── bootstrap.dart             binding, InitService().init(), runApp
│   │   ├── init_service.dart          LocaleSettings, Debouncer, diInitializer, Bloc.observer (+ DioLens.init after add-network-module)
│   │   ├── main_app.dart              MaterialApp.router + TranslationProvider
│   │   ├── di/
│   │   │   ├── di_container.dart      final diContainer = GetIt.instance
│   │   │   ├── di_initializer.dart    @InjectableInit(externalPackageModulesAfter: [<App>UtilsPackageModule, <App>NetworkPackageModule])
│   │   │   └── app_module.dart
│   │   ├── navigation/                <feature>_navigation_impl.dart
│   │   └── router/
│   │       ├── <app>_router.dart      <AppPascal>Router: GoRouter with <RouterPascal>Refresh; navigatorKey from DI (shared with DioLens)
│   │       ├── <app>_router_redirect.dart
│   │       └── <app>_router_module.dart <AppPascal>RouterModule, TOOL-OWNED — regenerated by add/remove-feature, regenerate-router
│   ├── core/
│   │   ├── di/core_module.dart        @preResolve PackageInfo
│   │   ├── data/models/error_model.dart           add-network-module — @freezed, ErrorModel.tryParse
│   │   └── network/                               add-network-module
│   │       ├── constants/api_paths.dart
│   │       ├── adapters/app_call_adapter.dart     <CallAdapter>: Retrofit call → TaskEither; DioException → ApiFailure
│   │       ├── failures/api_failure.dart          ApiFailure extends Failure (statusCode, ErrorModel?)
│   │       ├── di/network_config_module.dart      NetworkConfig (+ AuthInterceptor → AppAuthInterceptor)
│   │       └── interceptors/app_auth_interceptor.dart   auth_interceptor only
│   ├── features/<feature>/
│   └── generated/flutter_gen/
├── packages/
│   ├── clean_router/
│   ├── <app>_localization/
│   ├── <app>_network/                             add-network-module
│   └── <app>_utils/
├── assets/colors/colors.xml
└── build.yaml
```

The app's `pubspec.yaml` lists the packages `init` created under `workspace:`, and all of them as dependencies without a `path:` — pub resolves workspace members from the workspace. Each package pubspec has `resolution: workspace`, and the utils package depends on `<app>_localization` the same way.

Names, barrel imports and whether each package is created come from `clean-helper.packages.{utils,localization,router,network}` (the defaults are shown here). Packages with `create: false` aren't generated; when none are created, the app pubspec gets no `workspace:` key, because the packages live in an enclosing workspace.

## Workspace packages

### `clean_router` (`packages.router`)

Files and classes are named after the package (`<name>` / `<NamePascal>`; defaults shown):

- `lib/src/clean_router_base.dart` — `CleanRouterBase`, the interface for feature routers: `routes`, `refreshStreams`, `redirect(context, state)`, and `priority` (lower wins).
- `lib/src/clean_router_refresh.dart` — `CleanRouterRefresh`, a `ChangeNotifier` merging every router's `refreshStreams`, used as go_router's `refreshListenable`.

`<AppPascal>Router` and feature routers use `<RouterPascal>Base` / `<RouterPascal>Refresh`.

### `<app>_localization`

- `slang.yaml`, from the slang keys under `packages.localization` (defaults: output in `lib/src/generated`, `translate_var: locales`)
- the first locale file, `<input_directory>/<base_locale><input_file_pattern>` (default `assets/locales/en.locale.json`)
- the `String.tr` extension, and a barrel exporting the generated file

Slang runs inside this package.

### `<app>_utils`

```
lib/<app>_utils.dart                 barrel
lib/src/
├── app_logger.dart                  AppLogger (static)
├── bloc_observer.dart               AppBlocObserver
├── context_utils.dart               ContextUtils — root navigator/context, theme, media query, focus, snackbar, dialog, bottom sheet, clipboard, haptics, system UI
├── debouncer.dart
├── failure.dart                     Failure({message}); Failure.leftFromError(e)
├── type_definitions.dart            JsonDecodeFactory<T>
├── use_case_base.dart               UseCaseBase<ReturnType, ParameterType>
├── di/<app>_utils_module.dart       @module — registers BlocObserver
├── di/di_initializer.dart           @InjectableInit.microPackage → <App>UtilsPackageModule
├── di/di_container.dart             GetIt.instance (same instance as the app's), used by ContextUtils for the navigator key
└── functions/
    ├── get_current_function_name.dart
    ├── list_to_model_list.dart
    ├── safe_cast.dart               safeCast → Either<Failure, T>
    ├── safe_execute.dart            safeExecute(FutureOr<T>) → FutureOr<Either<Failure, T>> (eager)
    └── safe_execute_task.dart       safeExecuteTask(Future<T> Function()) → TaskEither<Failure, T> (lazy)
```

Dependencies: `flutter_bloc`, `fpdart`, `get_it`, `injectable`, `logger`, `<app>_localization`; dev `build_runner`, `injectable_generator`. Build_runner must run here before it runs in the app, so that `<App>UtilsPackageModule` exists.


### `<app>_network` (add-network-module)

An injectable micro-package (`<App>NetworkPackageModule`). It depends on nothing else in the workspace:

```
lib/<app>_network.dart               barrel
lib/src/
├── models/network_config.dart       @freezed NetworkConfig — the app registers one
├── network_di_keys.dart             NetworkDIKeys.noAuthDio            (auth_interceptor)
├── di/di_initializer.dart           @InjectableInit.microPackage
├── di/<app>_network_module.dart     @module: BaseOptions(NetworkConfig), RetrofitLogger as ParseErrorLogger,
│                                    Dio [AuthInterceptor, DioLens 'api'] + noAuthDio [DioLens 'no-auth'] (auth_interceptor)
├── interceptors/auth_interceptor.dart   abstract AuthInterceptor        (auth_interceptor)
└── utils/retrofit_logger.dart       logs parse errors via dart:developer (name: <app>_network)
```

The app supplies what the package can't: `NetworkConfig` (base URL, `User-Agent`) and, with `auth_interceptor`, an `AuthInterceptor` subclass, both from `lib/core/network/di/network_config_module.dart`. Errors are handled in the app, by its call adapter.

## Feature layout

```
lib/features/<f>/
├── di/<f>_module.dart                       add-feature --di
├── presentation/
│   ├── bloc/<f>/<f>_bloc.dart               @injectable; _event / _state are `part of`, @freezed
│   ├── page_providers/<f>_page_provider.dart   BlocProvider(create: diContainer) + navigation from DI
│   └── pages/<f>_page.dart                  pure UI, receives <F>Navigation
├── router/
│   ├── <f>_routes.dart                      sealed class <F>Routes { static const <camel> = '/<kebab>'; }
│   ├── <f>_navigation.dart                  abstract class <F>Navigation { goTo<F>([context]) }
│   └── <f>_router.dart                      @lazySingleton, implements <RouterPascal>Base
├── domain/                                  add-repo / add-entity
│   ├── entities/<r>_entity.dart
│   ├── repositories/<r>_repository.dart
│   ├── params/{get,post}_<r>_params.dart    --add-sample
│   └── use_cases/{get,post}_<r>_use_case.dart   --add-sample
└── data/
    ├── constants/<f>_api_paths.dart         REST
    ├── datasources/<r>_data_source_base.dart, rest_<r>_data_source.dart (REST)
    ├── models/requests/<r>_request_model.dart, models/response/<r>_response_model.dart   --add-sample
    └── repositories/<r>_repository_impl.dart
```

`lib/app/navigation/<f>_navigation_impl.dart` is `@LazySingleton(as: <F>Navigation)`. `goTo<F>([BuildContext? context])` uses the given context or falls back to `ContextUtils.currentContext` (the root navigator's), logs through `AppLogger.error` and returns if neither exists, then calls `.go(<F>Routes.<camel>)`.

## DI (get_it + injectable)

| Where | Annotation |
|---|---|
| Feature bloc | `@injectable` — a factory, because `BlocProvider` closes the bloc on dispose and a singleton would come back closed |
| Feature router, navigation impl | `@lazySingleton` / `@LazySingleton(as: …)` |
| Repository impl | `@Singleton(as: <R>Repository)` |
| REST datasource | `@Injectable(as: <R>DataSourceBase)` with a `@factoryMethod` factory |
| `NetworkConfigModule`, `CoreModule`, `AppModule`, utils / network package modules | `@module` |

`ParseErrorLogger` is registered once, as `RetrofitLogger`, by the network package's module (`@LazySingleton(as: ParseErrorLogger)`), so REST datasources can take it from DI.

## Result type — fpdart `TaskEither`

Every layer returns fpdart `TaskEither`:

```
AppCallAdapter<T> extends CallAdapter<Future<T>, TaskEither<Failure, T>>   (the app's, lib/core/network/adapters/)
  adapt(call) => TaskEither.tryCatch(call, …)          lazy: nothing runs until .run(); DioException → ApiFailure
<R>DataSourceBase / Rest<R>DataSource   → TaskEither<Failure, <R>ResponseModel>
<R>Repository / <R>RepositoryImpl       → TaskEither<Failure, <R>Entity>   (impl not async; TaskEither is covariant)
Get/Post<R>UseCase                      → TaskEither<Failure, <R>Entity>
UseCaseBase.call                        → FutureOr<TaskEither<Failure, ReturnType>>
```

Callers run `await useCase(params).run()`.

retrofit_generator still emits `_setStreamType<Either<Failure, T>>` in `.g.dart` files. This is harmless.

## Network

| Piece | Location | Notes |
|---|---|---|
| `ApiPaths.baseUrl` | `core/network/constants/api_paths.dart` | |
| `NetworkConfigModule` | `core/network/di/network_config_module.dart` | `NetworkConfig` (base URL, `User-Agent` from `PackageInfo`); with `auth_interceptor`, `AuthInterceptor` → `AppAuthInterceptor(noAuthDio: @Named(NetworkDIKeys.noAuthDio))` |
| `AppAuthInterceptor` | `core/network/interceptors/` | TODOs for `getAccessToken`, `refreshAccessToken`, `onRefreshFailed` |
| `ErrorModel` | `core/data/models/` | `{"errors": [...]}`; `ErrorModel.tryParse(data)` returns null for other bodies (TODO: adapt to your backend) |
| `ApiFailure` | `core/network/failures/` | `Failure` with `statusCode` and the parsed `ErrorModel` |
| `Dio`, `RetrofitLogger` | network package | see `<app>_network` above |
| `DioLens.init` | `app/init_service.dart` | Added by `add-network-module` after `Bloc.observer`, with the DI navigator key and `themeMode: .system` |
| call adapter | app, `core/network/adapters/app_call_adapter.dart` | class from `packages.network.call_adapter_name` (default `AppCallAdapter`); logs the error, returns the `Failure` as-is, wraps other errors, turns `DioException` into `ApiFailure` with the message from `ErrorModel` |
| `<F>ApiPaths` | `features/<f>/data/constants/` | `static const <camelRepo> = '/api/<kebab-feature>/'` |

The REST datasource imports the call adapter from `../../../../core/network/adapters/app_call_adapter.dart`, and `Failure` from the utils import.

## Other generated pieces

- **Serialization:** models are `@freezed sealed class … implements <Entity>` with `fromJson`. Request models are `@JsonSerializable`.
- **Localization:** slang; `LocaleSettings.useDeviceLocale()` in `InitService`, `TranslationProvider` in `MainApp`.
- **Assets:** flutter_gen via `build.yaml`, output in `lib/generated/flutter_gen/`, colors from `assets/colors/colors.xml`.
- **Lints:** `init` writes the full rules once — in the app, or, in a monorepo app with `use_root_analysis` (the default), in the workspace root with the app including it. Existing files are replaced unless `overwrite_analysis_options: false`. Each package's `analysis_options.yaml` only has `include:` pointing at the app's (or the root's) file.
